# Design tokens + UI components Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Minimal `apps/web` (Astro) with light/dark tokens, base components, and an internal `/internal/komponen` (rencana awal `/internal/komponen`; Astro mengabaikan halaman berawalan `_`) page.

**Architecture:** `src/styles/tokens.css` (custom properties, light in `:root`, dark via `[data-theme=dark]` and `prefers-color-scheme`), `src/styles/base.css`; components in `src/components/`; tests render with `experimental_AstroContainer`.

**Tech Stack:** Astro 7.4, Vitest 4.1, fontsource.

**Spec:** `docs/superpowers/specs/2026-11-25-ui-design.md`

## Global Constraints

- Colors only via tokens; text on `--color-accent` uses `--color-on-accent`.
- Interactive elements min 44 px; contrast ≥ 4.5:1 for every text/background pair used.
- No client JS except the theme toggle.

## Review Focus

- Dark mode via OS preference when no explicit choice; explicit choice wins both ways.
- `localStorage` unavailable (private mode) → toggle still works for the page, no error.
- WhatsApp button: `target=_blank` with `rel="noopener noreferrer"`, number digits only.
- Input/Select always have an accessible label (visible or `aria-label`) and show error text linked by `aria-describedby`.
- Focus ring visible on all interactive elements in both themes.
