# apps/api Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hono app on Workers with `/api/v1/health`, standard errors, request id, security headers, fail-closed role guards.

**Architecture:** `src/app.ts` builds the Hono app (`createApp()`), `src/index.ts` exports it for Workers; middleware and routes in focused files; tests run in workerd via `@cloudflare/vitest-plugin` using `SELF.fetch` / `app.request`.

**Tech Stack:** Hono 4.13, Wrangler 4, Vitest 4.1 + @cloudflare/vitest-plugin 1.8, Zod via `@pusatk3/shared`.

**Spec:** `docs/superpowers/specs/2026-11-25-api-design.md`

## Global Constraints

- Every error body parses with `apiErrorSchema`; codes/statuses from `ERROR_HTTP_STATUS`.
- Guards never call `next()` until Fase 2 (always 401 `UNAUTHORIZED`).
- No PII in logs; no stack/message of unexpected errors in responses.
- New deps listed in PR with reasons.

## Review Focus

- Unknown path under and outside `/api/v1` → 404 JSON (not Hono's text "404 Not Found").
- Wrong method on `/health` (POST) → 404 or 405 JSON, never HTML/text.
- Thrown non-Error values (`throw 'x'`) → 500 JSON.
- Malformed JSON / wrong content-type on a validated route → 400/422 JSON.
- Error responses also carry security headers and `X-Request-Id`.
