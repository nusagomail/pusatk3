# packages/db Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** D1 + Drizzle package with first migration, idempotent seed, and `GET /api/v1/categories`.

**Architecture:** `packages/db` holds schema, CSV parser, seed function (runtime-agnostic). `apps/api` binds D1 as `DB`; tests apply migrations in workerd via `@cloudflare/vitest-plugin` (`readD1Migrations` + `applyD1Migrations`) and seed with the CSV imported `?raw`.

**Tech Stack:** drizzle-orm 0.45, drizzle-kit 0.31, ulid, tsx, wrangler 4.165.

**Spec:** `docs/superpowers/specs/2026-11-25-db-design.md`

## Global Constraints

- No hand-written SQL in code; migrations only from `drizzle-kit generate` and reviewed.
- Never touch remote D1 (`--remote`) from a session.
- Enum values (`issuers`) validated with `@pusatk3/shared`.

## Review Focus

- Seeding twice keeps 14 fields / 59 categories / 8 cities and updates changed names.
- CSV with quoted commas/newlines in `catatan`/`regulasi` parses correctly.
- Unknown issuer code or duplicate slug in CSV fails loudly.
- `/categories` returns fields in `sort_order` and categories in CSV order.
- `/categories?x=1` → 422; works without any auth header.
