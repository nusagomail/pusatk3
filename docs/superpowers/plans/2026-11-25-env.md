# Cloudflare environments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** staging/production wrangler environments for api and web, staging resources, noindex for non-production web builds, stricter guard hook.

**Spec:** `docs/superpowers/specs/2026-11-25-env-design.md`

## Global Constraints

- Never run anything with `--remote` or deploy from the session.
- Production IDs are placeholders filled by the owner; no secrets in any file.
- Do not touch non-PusatK3 resources in the Cloudflare account.

## Review Focus

- `wrangler` env blocks do not inherit `vars`/`d1_databases`: each env must declare them.
- A build without `DEPLOY_ENV=production` must never be indexable.
- Guard hook must not block harmless commands (e.g. `git log --remote`-like text is irrelevant; only d1/db:* with --remote).
- Production config must keep workers_dev/preview_urls off and observability off.
