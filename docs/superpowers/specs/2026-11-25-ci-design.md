# Desain: GitHub Actions — CI dan deploy (issue #8)

Status: disetujui pemilik, 25 November 2026 (opsi A: tanpa secret, deploy staging dilewati dengan pesan jelas; `main` tetap hijau).

## Maksud

Setiap PR dicek otomatis; `main` otomatis ke staging; production hanya manual dengan persetujuan pemilik.

## Tujuan

- `ci.yml`: install (cache store pnpm saja), lint, typecheck, test, build pada PR dan push ke `main`; izin baca saja; PR lama dibatalkan.
- `deploy-staging.yml`: setelah CI sukses di `main` (`workflow_run`), environment `staging`: migrasi D1 staging, deploy API (`APP_VERSION` = SHA), build + deploy web (`CLOUDFLARE_ENV=staging`), uji asap health + beranda. Tanpa `CLOUDFLARE_API_TOKEN`: dilewati dengan notice.
- `deploy-production.yml`: `workflow_dispatch` saja, dari `main`, environment `production` (reviewer wajib diatur pemilik). Ditolak bila ID D1 production masih teks penanda, beranda masih memakai jadwal contoh, atau secret belum ada. Cek ulang lint/typecheck/test sebelum deploy.
- Action pihak ketiga dikunci SHA (checkout v7.0.1, setup-node v7.1.0, pnpm/action-setup v6.1.1; semua ≥ 2 minggu).
- Tes struktur workflow dan skrip preflight production.

## Bukan tujuan

E2E Playwright di CI (#9), Dependabot (Fase 3), custom domain staging.

## Gerbang persetujuan

Workflow production dan secret: pemilik mengisi secret, mengatur reviewer environment `production`, dan memicu deploy production sendiri.
